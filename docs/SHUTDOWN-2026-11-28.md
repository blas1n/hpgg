7. **저장소: 포트폴리오로 공개 유지, HP 데이터만 제거** (오너 11-18 — star 유지 위해 같은 저장소)
   HP 약관 §9: 라이선스 종료 후 30일 안에 HP 데이터 삭제. §3: 데이터셋을 남에게 제공 금지 → 공개 저장소에
   이력으로도 남으면 안 된다. 테스트 픽스처는 11-28 전에 합성 데이터로 교체해 둔다 (별도 PR).
   1. 브랜치: `main` 외 전부 삭제 (`snapshots` 는 공개 데이터셋, `data/*` 포함 약 200개).
   2. 이력 정리 (새 mirror clone에서, 합성 픽스처 PR이 main에 들어간 뒤):
      - `data/` 는 경로째: `git filter-repo --invert-paths --path data/` (빈 `data:` 일일 커밋은 자동 제거).
      - 픽스처는 경로는 두고 **옛 내용만**: 픽스처 디렉터리(`tests/fixtures`, `tests/server/fixtures`,
        `web/tests/fixtures`, `web/tests/e2e-data`)의 이력상 모든 blob 중 현재 HEAD에 없는 것을 모아
        `--strip-blobs-with-ids` 로 제거. HEAD의 합성 픽스처는 남는다.
      - 그 밖에 이력에만 있고 HEAD에 없는 경로(`git log --all --diff-filter=D --name-only`)를 훑어 HP 데이터가 있던
        곳(예전 데이터 디렉터리, 리포트 초안 등)이 있으면 같은 방식으로 제거.
   3. 검증: `git log --all --stat -- data/` 비어 있음, 픽스처 경로의 blob이 HEAD 것뿐, `npm test`·`pytest` 통과.
   4. `git push --force --mirror` 대신 `main` 만 강제 푸시 (`refs/pull/*` 는 GitHub이 거부함).
   5. GitHub Support에 Sensitive data removal 요청 — PR 178개의 `refs/pull/*/head` 와 캐시된 커밋 뷰가 옛 커밋을
      계속 잡고 있다. 요청은 오너 계정으로 (문구는 Claude가 작성).
   6. Actions: 실행 기록(약 590개, 로그에 수집 출력)과 아티팩트(Pages 빌드, 데이터 포함) 전부 삭제.
      `collect-and-deploy.yml` 은 저장소에서 제거, `ci.yml` 은 합성 데이터로 계속 통과하게 둔다.
   7. README를 포트폴리오용으로: 무엇을 만들었는지, 구조, 화면(11-28 전에 찍어 둔 `docs/screenshots/`),
      데이터를 뺀 이유(HP 약관), 로컬 실행은 `DATA_DIR=web/tests/e2e-data`.
   8. Mac mini의 clone·worktree는 전부 지우고 새로 clone (옛 이력이 로컬에 남음).
